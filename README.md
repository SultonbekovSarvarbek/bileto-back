# bileto-back

API для мобильного приложения Bileto — перепродажа билетов между людьми.
Покупатель оставляет заявку (имя + телефон), она приходит операторам в Telegram, дальше сделку ведёт оператор.
Оплата проходит вне приложения. Покупатель платит сверх цены сервисный сбор 7%, а Bileto удерживает 10% из суммы продавца с каждого проданного билета.

**Стек:** NestJS 11, Prisma 5, PostgreSQL, JWT, Swagger.

## Запуск

```bash
npm install
cp .env.example .env            # заполнить DATABASE_URL, JWT_SECRET, ADMIN_API_KEY
npx prisma migrate dev          # создать таблицы
npm run start:dev               # http://localhost:3000/api, Swagger — /docs
```

Тесты идут на отдельной БД. Создайте `.env.test` — копию `.env` с другой базой (например, `bileto_test`) и `TELEGRAM_POLLING=false`:

```bash
npm run test:e2e
```

## Telegram

1. Создайте бота у [@BotFather](https://t.me/BotFather) → `TELEGRAM_BOT_TOKEN`.
2. Создайте группу операторов, добавьте туда бота.
3. Узнайте ID группы (например, добавьте в группу [@getidsbot](https://t.me/getidsbot); у групп он отрицательный, вида `-100…`) → `TELEGRAM_CHAT_ID`.
4. Перезапустите сервер.

Что приходит в группу:
- **каждая заявка** — объявление, количество, сумма билетов, сервисный сбор 7%, итог для покупателя, комиссия Bileto 10% и сумма продавцу (всё в сумах), имя и телефон покупателя и продавца.
  Кнопки: «🟡 В работу», «✅ Продано», «❌ Отменить». «Продано» списывает билеты с объявления.
- **каждое новое объявление** с фото билета и кнопкой «⛔ Снять объявление».

Кнопки работают через long polling, публичный адрес сервера не нужен.
Polling должен быть включён только у одного запущенного экземпляра.
Пока токен не задан, сообщения пишутся в лог сервера.

## Как это работает для пользователя

- **Регистрация / вход** — имя и номер телефона, без SMS. Повторный вход по тому же номеру открывает тот же аккаунт.
- **Номер продавца** в объявлении виден только размытым: `+998 90 ••• •• 67`. Связь идёт через оператора.
- **Купить** — заявка с именем и телефоном. Входить в приложение для этого не обязательно.
  Защита от спама: одна открытая заявка на объявление с одного номера и не больше 10 заявок в час.

## API (префикс `/api`)

| Метод | Путь | Кто | Что |
|---|---|---|---|
| POST | `/auth/login` | все | регистрация / вход: `name`, `phone` → `token` |
| GET / PATCH | `/me` | пользователь | профиль (имя, язык `ru`/`en`/`uz`) |
| GET | `/listings?city=&q=&page=` | все | лента активных объявлений, поиск по названию и сектору |
| GET | `/listings/:id` | все | объявление (номер продавца размыт) |
| POST | `/listings` | пользователь | создать (multipart: поля + файл `proof`, фото билета) |
| PATCH / DELETE | `/listings/:id` | продавец | изменить / снять с продажи |
| GET | `/me/listings` | продавец | мои объявления |
| POST | `/requests` | все | заявка на покупку: `listingId`, `qty`, `name`, `phone` |
| GET | `/me/requests` | пользователь | мои заявки и их статусы |
| GET / PUT / DELETE | `/me/favorites`, `/favorites/:listingId` | пользователь | избранное |
| GET | `/admin/listings`, `/admin/listings/:id/proof`, `/admin/requests` | `X-Admin-Key` | запасной доступ для операторов |
| POST | `/admin/listings/:id/reject`, `/restore` | `X-Admin-Key` | снять / вернуть объявление |

Подробности и схемы — в Swagger: `/docs`.

Вход без SMS означает, что любой, кто знает номер, может войти в чужой аккаунт.
Поэтому админские эндпоинты закрыты отдельным ключом `ADMIN_API_KEY`, а не ролью пользователя.
